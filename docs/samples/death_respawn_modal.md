# death_respawn_modal
{: .no_toc }

A full-screen, post-mortem death modal showcase for the SUI Designer. Massive crimson "YOU DIED" headline, a muted cause-of-death blurb, a tidy end-of-life stats card (kills / time alive / distance traveled), a live amber respawn countdown, and a primary `RESPAWN` + secondary `Spectate` action pair stacked at the bottom.

## Overview

The sample exists to demonstrate four ideas at once:

- **OneWay bindings driving six different text strings** from controller-side state.
- The **single-variable button-text swap** pattern — one bound string flips between `"Waiting (Ns)..."` and `"RESPAWN"` instead of two buttons + an enabled flag.
- **Code-mode `OnClick` handlers** wired through the `Hud.OnXxxClick = ...` Action properties.
- The **`Show(...)` public API** that opens the modal with fresh stats from gameplay damage code.

The wrapper class `DeathRespawnModal` is generated by the SUI Designer from `death_respawn_modal.sui` on first compile, into `Code/Samples/DeathRespawnModal/` under the namespace `Sandbox.Samples`.

---

## What you'll see

A full 1920 x 1080 backdrop tinted near-black (`#000000ee`) drops over the camera. Centered against the middle of the screen sits the bold crimson "YOU DIED" headline at 96px, then a muted slate cause-of-death line ("Killed by Unknown" by default) ~120px below it.

Below that, a rounded 600 x 200 stats card with dark slate background lists three rows of `label: value` pairs — kills (highlighted in green), time alive, distance traveled.

Under the card, a 32px amber countdown line ticks `"Respawn in 3..."` -> `"Respawn in 2..."` -> `"Respawn in 1..."` -> `"Ready!"`. Then the green primary RESPAWN button (240 x 56) and the dark grey Spectate button (200 x 40) stack vertically.

While the countdown is running the primary button reads `"Waiting (Ns)..."` and clicks silently no-op; once the countdown hits 0 the label flips to `"RESPAWN"` and clicking actually fires the respawn handler.

## How to use

1. **Drop the controller on any GameObject.** It's `Sandbox.Samples.DeathRespawnModalController`. Default values produce a 3-second respawn countdown with placeholder stats.
2. **Hit Play.** The modal mounts immediately — `Hud.Show( GameObject, SuiInputMode.MouseOnly )` in `OnStart` grabs mouse input for the buttons without stealing keyboard focus from gameplay (chat, console, etc. keep working).
3. **Watch the countdown.** Amber text and the primary button label both tick down in real time. Until it hits zero, clicking RESPAWN is a no-op so the "waiting" affordance reads correctly.
4. **Click RESPAWN once it says RESPAWN.** The handler logs `[DeathRespawnModal] Respawning player.` and flips `IsOpen` to false (the modal stays mounted but stops updating — call `Hide()` or `Hud.Remove()` for a true tear-down).
5. **Click Spectate any time.** Always clickable, even during the countdown. Logs `[DeathRespawnModal] Switching to spectator mode.` so you can verify the wiring without writing real spectator code.
6. **Press K** (`Kill` action in the default s&box input layout — falls back to `Score` = Tab on layouts that lack Kill) to re-trigger the modal at any time. The hotkey calls `Show(DeathCause, KillsThisLife, TimeAliveSeconds, DistanceTraveled)` with the current inspector values, so you can hammer it to iterate on visuals without dying in real gameplay.
7. **Tweak in the inspector.** `RespawnDelaySeconds`, `DeathCause`, `KillsThisLife`, `TimeAliveSeconds`, `DistanceTraveled`, and `IsOpen` are all `[Property]` exposed. Flipping `IsOpen` off and back on resets the countdown.

## Variables

| Name | Type | Default | Role |
|---|---|---|---|
| `DeathCauseText` | `string` | `"Killed by Unknown"` | Cause-of-death blurb under the YOU DIED headline. Controller forwards `DeathCause` (the `[Property]` value, normalized to "Killed by Unknown" when blank). |
| `KillsThisLifeText` | `string` | `"0"` | Formatted kills count for the stats card. Controller writes `KillsThisLife.ToString()`. |
| `TimeAliveText` | `string` | `"0m 0s"` | Pre-formatted survival time. Controller computes from `TimeAliveSeconds` via `FormatTime` ("Mm Ss"). |
| `DistanceText` | `string` | `"0m"` | Pre-formatted distance traveled. Controller computes from `DistanceTraveled` via `FormatDistance` (source units / 39.37 -> metres). |
| `CountdownDisplayText` | `string` | `"Respawn in 3..."` | Amber line above the buttons. Controller updates each tick: `"Respawn in Ns..."` while waiting, `"Ready!"` once the countdown hits zero. |
| `RespawnButtonText` | `string` | `"Waiting..."` | Label of the primary button. Bound OneWay to `RespawnButton.ButtonText`. Controller flips between `"Waiting (Ns)..."` and `"RESPAWN"` — the single-variable swap that avoids needing a second button or an `IsDisabled` binding. |

All six are simple `string` Variables under the `Stats` / `Countdown` groups, written from the controller via `PushAll()` on every `OnUpdate` tick (and once from `OnStart` after `Show`).

## Bindings

| Element | Property | Variable | Mode | Trigger |
|---|---|---|---|---|
| `DeathCause` (Text) | `Text` | `DeathCauseText` | OneWay | OnChange |
| `StatKillsValue` (Text) | `Text` | `KillsThisLifeText` | OneWay | OnChange |
| `StatTimeValue` (Text) | `Text` | `TimeAliveText` | OneWay | OnChange |
| `StatDistanceValue` (Text) | `Text` | `DistanceText` | OneWay | OnChange |
| `CountdownText` (Text) | `Text` | `CountdownDisplayText` | OneWay | OnChange |
| `RespawnButton` (Button) | `ButtonText` | `RespawnButtonText` | OneWay | OnChange |

Every binding is OneWay because the modal is read-only — nothing here is ever edited by the player. The matrix at `Code/Runtime/SuiBindingModeMatrix.cs` confirms `Text.Text` and `Button.ButtonText` are both OneWay-capable, and `SuiDocumentValidator` flags typos at load time.

Notice that the labels for each stat row (`StatKillsLabel`, `StatTimeLabel`, `StatDistanceLabel`) are **unbound** — they're authored as static design text because the labels never change, only the values do.

## Events

| Element | Event | Mode | Handler | Wired via |
|---|---|---|---|---|
| `RespawnButton` (Button) | `OnClick` | Code | `OnRespawnClick` | `Hud.OnRespawnClick = OnRespawnClick;` in `OnStart` |
| `SpectateButton` (Button) | `OnClick` | Code | `OnSpectateClick` | `Hud.OnSpectateClick = OnSpectateClick;` in `OnStart` |

`OnRespawnClick` gates on the private `_canRespawn` flag — while the countdown is still running, the click is a silent no-op so the "Waiting (Ns)" label reads truthfully. `OnSpectateClick` is unconditional.

> WARNING — **Assign every Code-mode delegate BEFORE you call `Show(...)`.**
> The wrapper hands these `Action` pointers to the renderer Panel inside `SyncFieldsTo`, which runs as part of `Show`. Anything you assign **after** `Show` lands on the wrapper but not on the live Panel — the click silently no-ops forever. Same gotcha that `counter_button` and `settings_full` document. The controller follows the rule explicitly:
>
> ```csharp
> Hud.OnRespawnClick = OnRespawnClick;
> Hud.OnSpectateClick = OnSpectateClick;
> Hud.Show( GameObject, SuiInputMode.MouseOnly );
> ```

## Extending it

A few directions worth exploring once you've got it on screen:

1. **Hook to real damage flow.** Replace the `Input.Pressed( "Kill" )` debug hotkey with a real death event from your health component. When the player pawn dies, gather the cause string, kill count, lifetime, and distance, then call `Show(cause, kills, time, distance)` once. The modal becomes a pure receiver — drop one per HUD prefab and never touch it from gameplay logic again.
2. **Wire RESPAWN to your spawn system.** Inside `OnRespawnClick`, after the `if ( !_canRespawn ) return;` guard, fire your spawn flow — destroy the ragdoll, spawn a fresh pawn prefab on a `SpawnPoint`, fade the camera back in over a coroutine. The sample's no-op `IsOpen = false` is just a placeholder.
3. **Build a real spectator switch.** Replace the `OnSpectateClick` log with a camera handoff — point your `CameraComponent` at the player who killed you (or the nearest teammate), set a "spectating" flag on your pawn so movement input is ignored, and lower the modal opacity so the spectator view is visible behind it.
4. **Add a "killcam" replay above the stats card.** The headline currently sits at Y=-200 from middle-centre — you've got the entire top third of the screen free. Drop a `RenderTexturePanel` showing a 3-second replay from the killer's POV, captured server-side and streamed to the client on death.
5. **Customise the cause-of-death string per weapon.** Pass richer cause strings from your damage handler: `"Killed by Player47's M4A1 (Headshot)"` instead of `"Killed by Unknown"`. The `var_death_cause_text` Variable is just a string — any formatting your damage system can produce works.
6. **Promote `RespawnButtonText` swap to a CSS class.** Instead of toggling the string, leave the label as `"RESPAWN"` always and add/remove a `.disabled` class on the button via `Hud.View?.RespawnButton.SetClass( "disabled", !_canRespawn )` (requires exposing `RespawnButton` as a Variable — already true). Style the disabled state with greyed-out background and a wait-cursor.
7. **Per-player stats card.** Pass a `Dictionary<string, string>` of stat-name -> formatted-value pairs to `Show(...)`, then add Variables and bindings for additional rows (accuracy, headshot %, weapon used, etc.). Each row becomes another `(label, value)` pair following the same `stat-label` / `stat-value` class pattern.

## File map

```
samples/showcase/death_respawn_modal/
├── death_respawn_modal.sui            — V3 document (13 elements, 6 variables)
├── DeathRespawnModalController.cs     — Sandbox.Component, ~245 lines
└── README.md                          — this file
```

On first compile inside an s&box project, the Designer's generator drops:

```
Code/Samples/DeathRespawnModal/
├── DeathRespawnModal.razor            — generated renderer
├── DeathRespawnModal.razor.scss       — generated styles
└── DeathRespawnModal.cs               — generated wrapper (variables, Actions, View ref struct)
```

You only ever hand-edit `DeathRespawnModalController.cs`. The three generated files are regenerated from `death_respawn_modal.sui` on every doc save and should be treated as build output (don't commit edits to them — the Designer will overwrite).
